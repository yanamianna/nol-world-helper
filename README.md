# NOL 公演助手

个人使用的 Chrome / Edge Manifest V3 扩展，当前版本 **v0.1.9**，仅面向 NOL World 普通公演票。

**目前是官方入口与验证码辅助版本。** 可读取公开商品、票档和官方开售时间，保存联系人、张数与购票优先顺序，在开售时单次请求官方入场流程。选座图片验证码可由你点击后在本机识别，核对候选后填入，官网提交由你完成。自动选场、选座、锁座、填写订单、创建订单、支付识别及付款尚未接入。

长期目标是完成普通票流程：开售值守 → 官方验证与排队 → 场次与座位选择 → 官方确认锁定 → 资料填写 → 未支付订单 → 支付准备。后续路线是开发计划，不能视为已经实现或真实购票成功。

## 当前能力与限制

| 功能 | 当前状态 | 范围 |
|---|---|---|
| 商品与官方开售时间 | 已实现 | 识别商品 / 场馆编号，读取公开票档、价目及 `salesinfo` 开售起止时间；区分普通开售与会员预售，显示北京时间和韩国时间 |
| 普通票任务与联系人 | 已实现 | 多任务、本机联系人、张数、日期 / 时间 / 票档 / 座区优先顺序；同一浏览器只运行一个任务 |
| 前台值守与官方入场 | 已实现，真实账号入场待验收 | 保存及启动时重新读取官网时间，值守时每分钟复核；到时在正常网站会话中完成可交互验证，单次调用官方入场 API，再沿官方跳转继续 |
| 排队观察与人工接管 | 部分适配 | 已观察桌面繁中队列的商品全名、顺位及等候人数；同一任务标签可继续观察已确认队列，不重复入场；未知页面暂停 |
| 购票选择与订单校验 | 仅配置及纯函数 | 日期、指定时间、档位编号、座区、张数、币种及含费金额必须匹配；选择顺序先于价格，同一选择先座区优先再低价；不设价格上限 |
| 本机图片验证码辅助 | 已接入，真实网站准确率待验证 | 本机 ddddocr 给出六位字母候选，人工核对后填入；不点击官网提交，不处理 Turnstile，不自动刷新或重试 |
| 实际场次选择 | 未实现 | 尚未取得正常响应中的正式场次 ID；商品编号、日期区间和预售编号不能代替场次 ID |
| 实时座位读取与选择 | 未实现 | 静态座区图已观察，尚未读取实时可售座位 ID、排号、座号或组合出指定张数 |
| 服务端锁座与释放 | 未实现 | 已定位源码中的临时预选及确认接口，尚无真实成功、冲突、部分锁定、到期或释放回执 |
| 资料填写与订单创建 | 未实现 | 本机联系人未接入正式订单页；未创建真实订单，未验证提交结果核对和防重复提交 |
| 支付准备与付款 | 未实现 | 未适配渠道、最终金额、支付提交或结果核对；当前不自动付款 |

开售时间只使用官方接口，不允许手动填写。官网缺少有效时间、预售类型不明确或接口失败时不启动。休眠、浏览器重启或错过触发窗口后需要重新检查并启动，不静默补发。登录、会员资格和网站挑战沿官方流程处理。

v0.1.8 删除非普通票任务支持。旧非普通票任务保留在本机供删除，禁止保存或启动；更新后发现正在运行的旧任务会停止。旧普通票的档位显示名兼容读取为 `gradeLabel`，不再保留旧人数字段；实际匹配仍使用档位编号及座区，不凭显示名称判断库存。

v0.1.9 修复开票时遇到公告、关闭后仍停在人工接管的问题。请先自行阅读并处理官网提示，再点击页面助手的“已处理提示，继续”。扩展在原标签重新核对官网时间，只有从未启动过入场的任务才能继续；关闭公告本身不会触发入场，已派发或结果不明的任务不能用此按钮重试。

验证组件现在等待 [Cloudflare 官方就绪回调](https://developers.cloudflare.com/turnstile/get-started/client-side-rendering/)，复用官网脚本并保留官网回调。脚本加载失败、加载超时、就绪超时和窗口创建失败分别显示固定诊断码。旧版 `ENTRY_SDK_UNAVAILABLE` 混合多种失败，不能据此判断是代理问题；这些失败发生在入场 POST 之前时，可使用官网购票按钮手动继续。不会自动重试验证或入场请求。

## 已观察的真实普通票流程

2026-10-08，在用户正常 Edge 会话中手动点击 [JEONGHAN × JOSHUA 普通票](https://world.nol.com/zh-CN/ticket/places/26001167/products/26013793) 的“先行订购”，同标签跳转官方 partner gate。最初售票域名连接超时，用户更换代理后正常进入官方队列，并自动到达 `/onestop/schedule`。

选场页默认显示 2026-10-30、韩国时间 19:00。为查看后段，点击一次官网“下一步”，进入 `/onestop/seat`，看到商品全名、场次、实际座区图、倒计时和图片验证码。默认日期只记录页面状态，不是实验购买配置。验证码未完成，最终出现官网“10分钟的座位选择时间已超过／请重新开始预订”提示。**没有选择或锁定座位，没有创建订单或付款。**

这些证据验证了官网正常按钮、排队和跳转流程，不能证明扩展入场 API 已通过真实账号验收。扩展只读识别已观察的目标选座布局、验证码与过期弹窗；其他商品、场次或布局仍交人工检查。详见 [预选档位与实际流程记录](extension/docs/selection-and-hold.md)。

公开商品、Partner / Global gate 及 OneStop 脚本已定位入场、排队、座位状态读取、GraphQL 临时预选和 REST 完成选座确认。这些是**源码证据**，尚无真实预选或锁定成功响应，也没有启用后段请求。详见 [锁票请求与响应研究](extension/docs/hold-protocol-research.md) 和 [OneStop 技术研究](extension/docs/onestop-flow-research.md)。

## 普通票后续路线

每阶段先取得正常官方页面及响应证据，再进行模拟验证和明确配置下的真实验收，通过后才启用下一阶段。

| 阶段 | 开发内容 | 启用标准 |
|---|---|---|
| 1. 真实入场衔接 | 验证扩展入场 API、登录 / 会员资格、官方挑战、队列及失效恢复 | 正常会话可继续，不重复入场；未知结果先检查官网 |
| 2. 实际场次 | 读取日期、时间与正式场次 ID，按保存顺序匹配 | 使用页面实际 ID；首选确认不可买后才考虑下一选择，不误选商品或场次 |
| 3. 座区与座位 | 映射票档和座区，读取实时状态、排号及座位 ID，支持分散座位 | 选足张数；显式档位及座区受约束，座区内再比较价格；库存变化时明确处理 |
| 4. 座位锁定 | 单次官方确认，核对锁定席位与数量，识别冲突、部分成功、期限及释放结果 | 高亮或点击不等于锁定；必须有官方确认。结果不明暂停，锁定成功后停止其他选择 |
| 5. 资料与未支付订单 | 按真实字段填写联系人，核对商品 / 场次 / 席位 / 张数 / 含费金额，查证提交结果 | 完成一次明确配置、已授权的未支付订单实验；提交不明先查订单，不重发，到付款前停止 |
| 6. 支付准备与结果 | 读取订单、支付时限、渠道及最终金额，衔接官方支付页 | 人工付款后核对订单及支付状态；返回不明时接管 |
| 7. 可选支付自动化研究 | 在订单流程稳定后逐渠道验证可适配步骤，默认关闭、显式启用 | 只针对明确授权的订单、渠道与最终金额；银行验证及未知步骤由本人处理，不能承诺无人值守付款 |

“不设价格上限”只描述选票规则，不代表授权对任意金额扣款。金额或必要费用未知时校验仍不通过。密码、登录令牌和支付信息不进入扩展长期存储。

后续状态需要区分“已选择”“官方确认已锁定”“已创建订单”和“已确认支付”。锁定到期、网络中断或结果不明时先核对官网现状；已有锁定、订单或支付处理中时不盲目切换选择，需要换选时先确认释放结果。

仍需取得正式场次、实时库存及一次明确日期、档位 / 座区、张数和联系人配置下的操作证据。此前获授权的一次未支付订单实验尚未完成，不包含付款授权。

## 安装与使用

1. 解压分发包，打开 `chrome://extensions` 或 `edge://extensions`，开启开发者模式。
2. 点击“加载已解压的扩展”，选择含 `manifest.json` 的 `extension` 文件夹。
3. 打开“设置”，保存联系人与普通票任务。粘贴商品链接后读取官网时间、选择开售阶段及购票顺序。
4. 更新时在扩展管理页重新加载；请在排队前完成更新，不要刷新正在排队的官网页面。

可选验证码辅助使用本机 [ddddocr](https://github.com/sml2h3/ddddocr)：运行分发包 `local-ocr` 中的安装、启动脚本，弹窗点击“启用本机识别”并授予本机权限。进入已适配页面后，点击“识别当前图片”，核对或修正候选，再点击“核对并填入”，最后由本人点击官网提交。详见 [本机服务说明](local-ocr/README.md) 与 [中文使用说明](extension/README.md)。

验证码辅助目前仅适配 JJ 普通票 26013793 / 26001167、2026-10-30 韩国时间 19:00 的已观察布局，也可用于手动进入的同一页面，不绑定或重建队列。图片刷新、弹层关闭或选座到期后丢弃旧候选；DOM 未变化不保证服务器仍接受图片。

## 本机数据与验证

任务和联系人保存在本机扩展存储，可单独删除或清除全部本机数据。可选 OCR 的图片和候选临时经过扩展消息及 `127.0.0.1:8765`，不上传外部 OCR，不进入存储、诊断、文件或日志。Turnstile 验证与入场凭据只在页面正常流程中使用；官方跳转地址只用于该次跳转，不保存进诊断。仓库不包含个人浏览器配置和实际联系人。

`scripting` 用于当前 NOL 商品页的正常同源入场流程；`webNavigation` 仅观察已有三个官方域名的活动购票主页面错误，诊断保存主机和固定错误码。失败后 URL 已还原时可能漏报，不能保证识别每次网络故障。[Chrome webNavigation](https://developer.chrome.com/docs/extensions/reference/api/webNavigation)、[Tabs URL 字段](https://developer.chrome.com/docs/extensions/reference/api/tabs#type-Tab)。

在仓库根目录运行：

```powershell
node --test extension/tests/*.test.js
python -m unittest discover -s local-ocr/tests -v
```

v0.1.9 的 **168 / 168 项 Node 测试通过**，新增 SDK 就绪 / 错误分支和公告恢复、并发点击、暂停 / 停止期间响应等回归。Edge / Chrome 各 22 项普通票界面检查和 10 项公告恢复检查通过：公告需人工处理，关闭不会自动入场，点击继续在同一标签单次提交，公告重开再次阻塞，已派发或结果未知时没有恢复入场按钮。基础模拟触发延迟为 21 ms / 15 ms；两类浏览器检查均无应用控制台错误 / 警告，公告检查无外部请求。测试只使用隔离配置与合成响应，不代表真实账号入场成功。复用脚本为 `extension/tests/modal_recovery_smoke.py`。

v0.1.8 的 **156 / 156 项 Node、19 / 19 项本机服务测试通过**。当时 Edge / Chrome 各 22 项普通票界面检查通过，覆盖仅普通票设置、旧任务禁用及不出现在弹窗、官方时间和单次入场；每浏览器仅一次模拟入场 POST，无提前或重复触发。本机触发延迟分别为 78 ms / 76 ms，不代表服务器入场或排队耗时。

实际 ddddocr 引擎的双浏览器各 10 项 OCR 检查通过：合成图 `ABCDEF` 返回原始 `aBCdeF` 并规范为 `ABCDEF`，人工修正 / 填入不提交，图片刷新、过期和服务失败正确失效。官网提交为零、控制台无应用错误。可选本机权限仅在隔离 manifest 副本模拟授予，未验证原生权限弹窗；真实 NOL 图片准确率及官网接受结果仍未验证。复用脚本为 `extension/tests/ocr_smoke.py`。

双浏览器另各通过 9 项弹窗状态、6 项队列观察检查，这两类检查没有入场请求、外发请求、应用控制台错误或警告。v0.1.7 的 151 项 Node 与假 OCR 引擎检查属于历史验收，不作为本轮真实模型证据。

其他隔离测试覆盖官方时间、时区、预售选择、休眠、重复触发、错误保留、队列数字与错商品、隐藏验证码、图片刷新、过期及服务失败。测试不使用个人浏览器会话，不访问真实库存或执行入场、锁座、下单、支付。源代码中的接口定位、隔离测试通过和真实官网业务成功分别记录，不能互相替代。
