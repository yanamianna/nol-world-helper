# 普通票预选档位与锁座研究

核对日期：2026-10-08，当前扩展 **v0.1.8**。仅研究普通公演票；当前提供官方入口、已观察队列的只读状态和可选本机验证码候选，尚未启用自动选场、选座或锁座。

## 目标行为与当前边界

正常通过官方认证、验证和排队后，读取实际场次可售座位，只考虑任务预选的档位、座区及张数，允许分散座位。首选确认不可买后，才按购票优先顺序考虑下一选择；同一选择先座区优先，再比较低价，不设价格上限。

高亮只是本地选择。必须由正式页面或正常响应明确确认当前会话已锁定哪些座位，才记录成功。锁定成功后停止其他选择，部分成功、结果不明或释放未确认时暂停接管。此流程尚未接入扩展。

任务只接受 `kind: 'ticket'`。每项购票选择使用 `date / time / gradeLabel / seatGrade / priceGrade / zones`；`gradeLabel` 只用于展示，不代替档位编号。旧普通票显示名兼容读取，旧非普通票任务禁止启动、保留供删除，更新时活动旧任务停止。

## 本轮普通票实际流程

2026-10-08，用户正常 Edge 会话中查看 [JEONGHAN × JOSHUA 普通票](https://world.nol.com/zh-CN/ticket/places/26001167/products/26013793)：

1. 商品页显示 Assigned Seat / General，公开票价 143,000 韩元，入口为“先行订购”。这仅表示存在会员预售入口，不代表账号有资格或仍有库存。
2. 关闭公告后手动点击一次官网入口，按钮禁用，同标签跳转 `tickets.interpark.com/gates/partner`。
3. 起初出现 `ERR_CONNECTION_TIMED_OUT`，未加载后段；用户更换代理后恢复访问，继续沿现有会话观察。

这是官网按钮的实际跳转，**不能作为扩展入场 API 的真实账号验收**。入场凭据没有保存进源码、诊断或本文。扩展保留准确入场错误和官方主页面导航错误，失败时提示接管，不自动重试或修复网络。

## 网络恢复与实际排队

网络恢复后，当前标签正常进入该普通票 `/waiting` 页面，显示商品全名、我的等候顺位和等候人数，顺位持续下降。观察期间没有刷新、重入或另建队列。

页面说明“订购率”指已完成付款的门票比例，正在付款的票也可能占用余量，因此不能将该比例换算为可选座位数。页面提示预约后有选座时限，刷新或重新连接会重置顺位。

已适配该桌面繁中布局：商品名为 `Wait_goodsName__Sjp96`，顺位为 `StatusBox_mainText__9gJXJ` 中的 `h3 / strong`，等候人数来自对应 `StatusBox_row__rN2QG`。识别要求官方精确路径、唯一数字、已观察结构和任务完整商品名匹配；不读取或保存队列 URL 参数，其他语言及布局人工处理。

公开 [排队页面脚本](https://tickets.interpark.com/waiting/_next/static/chunks/pages/index-68a114581efc8d15.js) 与 [共享脚本](https://tickets.interpark.com/waiting/_next/static/chunks/pages/_app-6db3b888368367a0.js) 显示：网站收到 `oneStopUrl` 后调用 `document.location.replace`。顺位为零不能代替正式页面已加载的结果。研究只匿名读取静态脚本，没有调用或重放队列接口。

扩展将实际观察队列记为 `queueObserved`，不篡改入场 API 回执。已确认的同任务队列可在回执不明后继续观察，晚到回执不能覆盖它，也不能触发再次入场。任务外的新队列目前不自动绑定。

## 已进入正式选场与选座页

沿现有队列，官网自动进入 `https://tickets.interpark.com/onestop/schedule`，没有 iframe。日历默认选中 2026-10-30，时间行显示 7:00 PM；10 月 31 日和 11 月 1 日按钮可用。按钮可用不代表有余票。

为查看后段，点击一次官网“下一步”，同标签进入 `/onestop/seat`。商品全名与普通票一致，场次为 `2026.10.30(周五) 7:00 PM`，显示选座倒计时、座区图及“完成選擇”。没有选座时确认按钮禁用，验证码提示“輸入文字後才能選擇座位”。

默认日期仅为观察状态，不是购买配置。验证码交由本人完成；没有选择、确认或锁定座位，没有订单或付款。

实际 DOM 包括商品标题 `SubHeader_headerTitle___LjIv`、场次 `SubHeader_scheduleDate__UaD4B`、验证码层 `ModalCaptchaText_layerWrap__jn1bV` 和座区图 `SeatMap_blockImg__QQUF7`。官方 SVG 为 [场馆底图](https://ent-ticketimage.interparkcdn.net/svg/26001167/ea91e9b960c8466bad10fea7bf8a44af.svg) 与 [座区图](https://ent-ticketimage.interparkcdn.net/svg/26001167/087dd34c78914d7c972c56fc356b0e3b.svg)，图形不是实时可售座位数据。

当前只读识别这一商品、场次及布局，核对商品 / 场馆、标题、场次和地图；未知页面交人工检查，不自动操作座位。可选 OCR 在本人点击后给出候选，核对后填入，官网提交仍由本人操作。验证码页脚结构修正依据官方公开组件，尚未在新真实会话中重验。

验证码没有完成，官网最终出现“10分钟的座位选择时间已超过”“请重新开始预订”，并移除地图。可见弹窗为 `div.nds-e-dialog__container[role="dialog"][aria-modal="true"]`，包含标题、说明及“确定”。扩展优先识别已适配超时层，避免使用底下旧验证码，不点击确定或自动重启。

## 尚缺的实际证据与下一步

1. 正常响应中的正式场次 ID，以及日期 / 时间与该 ID 的对应关系。
2. 预选档位、座区、逐座 ID、实时可售状态及指定张数的组合规则。
3. 一次正常完成选择的真实请求 / 响应，以及售罄、竞争冲突和部分成功返回。
4. 官方确认当前会话锁定的席位、张数、期限、释放及到期状态。未提供的字段保持未知。

下一步需要新的有效会话，由本人完成验证码后观察可售座位。真实锁座实验还需明确日期、档位 / 座区和张数，只沿正常官方流程操作，到付款前停止。详细公开接口与异常逻辑见 [OneStop 技术研究](onestop-flow-research.md) 和 [请求采样方法](hold-protocol-research.md)。

本轮实际 ddddocr 引擎在 Edge / Chrome 各通过 10 项合成图隔离检查：`ABCDEF` 返回原始 `aBCdeF` 并规范为 `ABCDEF`，候选、人工修正填写、图片更新、会话过期及服务失败均检查，官网提交为零、控制台无应用错误。权限通过隔离 manifest 副本模拟授予，原生权限弹窗未验收。该检查不证明真实 NOL 图片准确率，也不代替官网接受结果。

v0.1.8 共 156 项 Node、19 项本机服务测试通过；普通票界面双浏览器各 22 项通过。它们验证配置、恢复及模拟流程，不代表真实库存、锁座或订单已验证。

核心校验保留普通票显式档位、座区、日期 / 时间、张数和含费金额约束；未指定档位时保留任意档位语义。它仍是纯函数模型，尚未接入逐座库存组合或锁座请求。
