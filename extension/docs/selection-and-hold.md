# 预选档位与锁票研究

核对日期：2026-10-08。当前扩展 v0.1.5 尚未启用自动选票、选座或锁票。

## 希望实现的行为

在正常通过官方认证、验证和排队之后，读取该商品实际场次的可售项，只考虑用户预选的档位与数量。普通票可以选择该档位中符合座区偏好的任意可售座位；允许分散座位。Play＆Stay 则需要匹配酒店、房型、人数组合与套餐份数。首选确认为售罄后，才按购票优先顺序考虑下一选择。

选中或高亮只是本地选择。只有正式售票页面或正常响应明确确认库存已被当前会话锁定，才可以记录锁定成功。锁定成功后停止尝试其他选择。响应不明、部分成功或释放未确认时暂停接管。

## 本轮普通票实际流程

按用户最新指定，研究目标已切换为 [JEONGHAN × JOSHUA 普通票](https://world.nol.com/zh-CN/ticket/places/26001167/products/26013793)，商品 26013793、场馆 26001167。此前 TXT 和 JJ 酒店套餐只作为入口参照。

2026-10-08 晚在用户当前 Edge 中完成了以下观察：

1. 官方商品页显示 Assigned Seat / General，公开票价 143,000 韩元；预约按钮为“先行订购”。这表示当前提供会员预售入口，不代表账号已有资格，也不代表有库存。
2. 关闭商品公告后，手动点击一次官网“先行订购”。按钮随后禁用，页面在当前标签页正常跳转至 tickets.interpark.com 的 /gates/partner。
3. Edge 显示 ERR_CONNECTION_TIMED_OUT，未加载排队或选票页面。此前 TXT、JJ 酒店套餐同一售票域名也超时；没有通过改商品取得后段页面。

这验证了官网按钮的正常同标签跳转行为，**不等于扩展入场 API 已在真实账号中通过验收**。未获得正式场次 ID、实时座位、锁座请求或响应，没有锁票、创建订单或付款。跳转中的入场凭据未保存进源码、诊断或本文。

v0.1.5 针对本轮暴露的入口状态问题完善错误保留和恢复提示，并识别活动购票标签的官方主页面导航错误。它不会修复售票域名的网络连接，也没有开启未经观察的选座与锁座动作。要继续适配，需要该 Edge 会话能正常进入正式选座页；后续按用户指定的普通票流程采样。

## 需要取得的实际证据

1. 正常入场后的商品、场馆、日期、时间和实际场次编号；观察 iframe 或新窗口是否承载选票控件。
2. 普通票的档位、座区、座位 ID 与实时可售状态；套餐的档位、人数与“份数”的实际含义。不得用日期范围、预售编号或价格档编号代替场次 / 座位 ID。
3. 正常选票并完成选择后，网站怎样向服务器提交；售罄、竞争冲突及部分成功的实际返回。
4. 官方如何确认当前会话已锁定，实际锁定了哪些票 / 套餐、数量，以及是否提供有效期或释放方式。网站未提供的信息保持未知。

下一步优先观察用户指定的 JJ 普通票正式选座页。真实锁定实验需要明确实验场次、档位和数量；通过本人完成网站要求的认证与验证码后，沿正常官方流程验证。不执行付款。

## 本次代码修正与范围

v0.1.4 修复普通票选择校验遗漏档位的问题：配置中的 `seatGrade`、`priceGrade` 只要非空，候选都必须分别匹配；错档位、缺少已要求的档位不能通过，价格更低也不能越过限制。未选档位时保持原有座区偏好语义。

新增两项测试，验证错档位不能参与排序或通过订单校验，以及未选 / 单独选择档位编号的行为。现有套餐匹配、优先顺序和无价格上限规则保持不变。

这仍是纯函数校验。当前候选模型是一组完整购票选择，尚未实现从逐座实时库存组合出指定数量的座位，也未接入任何锁座请求。扩展进入未适配的正式售票页面时仍会提示人工接管。
