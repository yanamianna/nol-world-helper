# NOL 公演助手（Chrome / Edge，Manifest V3）

这是 NOL World 公演商品的任务设置和前台值守扩展。v0.1.4 只按官方接口返回的开售时间运行，无需也不能手动设置；到时在正常网站会话中完成官方验证并单次请求入场 API，再沿官方售票入口继续。登录、验证码和付款由你完成。不设价格上限，旧任务保存的预算也不再限制购票选择。

**当前交付范围**：商品信息读取、任务与联系人设置、前台倒计时、官方预约入口、暂停/停止/人工接管，以及订单配置校验逻辑。登录后的选场、选座、填写订单和 checkout 尚未完成真实流程验证，当前不启用这些后段的自动操作。页面截图对照和售票后段适配状态保留为待人工验证；不代表已经验证过下单成功。

完整的未完成清单和全流程开发路线见仓库 [README](../README.md)。后续目标包括实际场次 / 套餐 / 座位选择、官方确认的座位或套餐锁定、未支付订单，以及可选支付自动化研究。上述功能当前均未启用；本版本仍由你完成进入后的选票、下单和付款。

## 安装

ZIP 是源码分发包，需要先解压再加载；不是扩展商店的一键安装包。

1. 将提供的 ZIP 解压到一个固定文件夹，找到含 `manifest.json` 的 `extension` 目录。直接使用工作区时，该目录就是本 README 所在目录。
2. Chrome 打开 `chrome://extensions`；Edge 打开 `edge://extensions`。
3. 开启“开发者模式”，选择“加载已解压的扩展”，选中含 `manifest.json` 的目录。
4. 从工具栏打开“NOL 公演助手”，点击“设置”。更新源码后，在扩展管理页点击“重新加载”。

保留解压目录，移动或删除它会影响已加载的扩展。浏览器需要允许扩展访问实际使用的官方售票页面。

## 设置与值守

1. 在“联系人”中添加姓、名、邮箱、国家/地区电话代码和电话。姓名按实际证件填写。
2. 新建购票任务，粘贴 `https://world.nol.com/{语言}/ticket/places/{placeCode}/products/{goodsCode}`。输入完成后自动读取商品、公开票档和开售时间；失败时可点击“重新读取”。
3. 选择普通公演票或 Play＆Stay 套餐、普通或会员先行开售阶段。开售时间只读显示，同时显示北京时间与韩国时间；只有一个有效预售窗口会自动选择，有多个则选择对应预售类型。官网缺少有效起止时间或读取失败时，任务不能保存 / 启动，点击“重新读取”或稍后再试。填写数量和联系人，无需设置预算。
4. 设置“购票优先顺序”：第一选择最想买，无法购买时再考虑第二选择，以此类推。每个选择包含演出日期/时间及酒店或票档。演出日期/时间按韩国时间（UTC+9）填写，韩国时间比北京时间快一小时。
5. 保存后开始值守，同时只运行一个任务。保持浏览器与任务页面在前台，电脑不要休眠。
6. 保存及启动时后台都会重新取官网时间，旧任务的手动时间会被替换。值守期间每分钟复核；官网延期开售会自动调整倒计时，接口异常、开售窗口消失或变更后已过时间则暂停。
7. 到时先检查官网账号票务状态，显示正常 Turnstile 验证；若出现挑战，由你完成。通过后单次 POST `/api/users/enter/token` 并跳转官方 partner gate，不点击购票按钮兜底。遇到登录 / 邮箱未完成、验证失败、接口响应不明确或未适配页面时，按提示人工接管。付款始终由你决定并操作。

过去的开售时间可以保存，但不会通过普通“开始值守”补触发；确需立即进入时，使用明确的“立即开始”。后台、休眠或计时出现较大跳跃时，不会承诺准点触发，也不会静默补发预约动作。已经领取过的入口动作不会再次触发。

保存任务并不代表取得先行购票资格，也不代表有库存。商品编号区分商品，演出日期/时间区分场次，套餐档位区分酒店与人数；这些项目需要分别核对。

## 数量、套餐与购票顺序

- 普通票的数量是张数；套餐的数量是套餐份数，方案中的“人数”是每份套餐的人数。双人套餐一份不能当成购买两份。
- 购票选择按保存顺序检查；显式指定的顺序优先于价格。普通票在同一选择中先按座区优先级，再比较低价；套餐按酒店/人数/档位配置匹配，不自行替换为其他酒店或人数。
- 普通票显式选择的票档与价格档编号也必须匹配；未选择票档时保留座区偏好。这是待接入真实页面的选择校验，当前不会自动锁票。见 [预选档位与锁票研究](docs/selection-and-hold.md)。
- 商品、场地、日期、指定时间、票档/套餐、座区或数量不符合任务时，订单校验不通过。
- 不设价格上限，已确认的高金额不会因价格而排除。金额或手续费未知、币种不一致时，校验仍不通过，交由你核对。公开价目表不是最终含费金额。

校验函数已有单元测试；它不等于真实 checkout 页面已适配。当前后段自动化保持关闭，待正常登录后的官方售票页面验证后再接入。

## 实测状态与本机数据

TXT 的真实公开商品页已只读核对，预约按钮结构存在且唯一。登录后的真实队列和订单流程没有完成实测，没有创建真实订单或支付。一次未支付订单实验已有授权，目前还缺已登录的可访问会话，以及实验套餐、数量和联系人配置；这些值需要由你填写。

当前扩展读取公开票档与价目，未接入演出分区自动识别、实时余票或具体座位 ID。已从 JEONGHAN × JOSHUA 官方说明图确认 FLOOR F1–F8、1F 102–105/110–114、2F 202–214、3F 308–314 的静态布局；其中 102、202、114、214、314 区的部分座位可能受限。该静态图不代表实时可购座位，套餐的 1–24 档是酒店/人数方案。[官方说明图](https://ticketimage.interpark.com/Play/ITM/Data/Modify/2026/9/2026092313042548.jpg)。

v0.1.4 的 68 项 Node 测试通过，新增预选档位校验。v0.1.3 的 Edge / Chrome for Testing 20 个隔离场景已通过；本次未修改界面与入场流程，没有重复浏览器验收。覆盖只读官网时间、多预售类型、后台覆写旧手动时间、接口异常暂停、验证取消、单次模拟入场 POST、无按钮点击及刷新不重复；设置页、390 窄屏和360弹窗检查通过，控制台无应用错误或警告。浏览器测试使用隔离配置和 Turnstile 测试替身，不使用个人浏览器会话；本地触发耗时（Edge 60 ms、Chrome 93 ms）不是到达网站服务器的时间保证。

浏览器集成测试使用离线页面及公开匿名数据夹具，不代表真实库存、排队、登录后选票或下单已验证。

任务和联系人保存在本机扩展存储中。可以在设置中删除联系人/任务，或使用“删除全部本机数据”。官方验证及入场凭据只在 NOL 页面内存中使用，不经过扩展消息、存储或诊断。新版本新增 `scripting` 权限，仅用于在已授权 NOL 商品页运行这段同源接口流程；更新后需在扩展管理页重新加载，按浏览器提示允许该权限。

## 验证

在仓库根目录运行：

```powershell
node --test extension/tests/*.test.js
```

测试覆盖开售时间、前台/休眠/重复触发、无价格上限与费用未知、商品和场次匹配、套餐人数与份数，以及购票优先顺序等高风险规则。单元测试不验证官方售票页面的实时库存、排队、验证码或成功下单。

测试需要 Node.js 22 或更新版本。浏览器集成脚本 `tests/browser_smoke.py` 还需要现有 Python Playwright 与浏览器运行时；这些都是开发验证依赖，安装扩展本身无需 Node.js、Python 或服务器。数据夹具包含在源码中，测试不会使用个人浏览器配置。
